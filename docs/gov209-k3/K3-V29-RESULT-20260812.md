and fired only on `exit_reason IN ('stop','trail')`. The 08-11/08-12 loss attribution replayed
every re-entry that followed a same-symbol losing exit within 120h:

| re-entry | gap after the loss | scope | outcome |
|---|---|---|---|
| WMT | 71h | same direction | **−136.80** |
| WST | 72h | **cross-direction** (prior exit was `manual`) | **−103.23** |
| AVB | 96h | **cross-direction** | **−107.68** |
| WMB | 91h | same direction | **−341.14** |
| WSM | 114h | same direction | **−96.86** |

**All five lost — −$785.71 — and zero winning re-entries occurred inside any 120h window.**
The first winners after a loss came at 142h (WSM +485) and 240h (AKAM +555). The old 24h rule
caught none of the five; each dimension of the extension is carried by specific rows:

- **120h (~3 sessions):** all five gaps sit in 71–114h.
- **Symbol-wide:** WST and AVB re-entered the *opposite* direction and lost anyway.
- **Any losing exit:** WST#2's prior loss was labelled `manual` — the `stop/trail` list would
  have missed it at any window width.

## 2. The mechanism

Three `quantum.gate_config` flags govern the block, read inside the function with the house
fail-closed pattern — a missing or nonsense flag can only make the rule *stricter*:

| flag | live value | if missing/invalid |
|---|---|---|
| `k3_cooldown_hours` | 120 | 120 (and `<= 0` clamps to 120 — a zero can never silently disable K3) |
| `k3_symbol_wide` | 1 | 1 |
| `k3_any_loss_exit` | 1 | 1 |

Predicate now: `status='closed' AND net_pnl < 0 AND (any_loss OR exit_reason IN ('stop','trail'))
AND exit within window AND (symbol_wide OR same direction)`. Winner exits still **never** cool
down (the v2.2 promise, kept). Signature unchanged — `p_cooldown_hours` remains but is
superseded. **Rollback:** set the flags to 24/0/0 and v2.2 behaviour returns exactly (proven
live, fixtures S5a/S5b). The rejection payload now reports `cooldown_scope` alongside
`cooldown_hours`.

## 3. How it shipped — a self-verifying migration

The migration did not carry a 20KB retyped function body. It made Postgres patch its **own
deployed def** with the same six count-asserted substitutions as the reviewed patch, then
aborted atomically unless the result's md5 equalled the reviewed artifact's md5. Baseline
guard: deployed md5 must be v2.8's `625b111e…` before touching anything. Post-EXECUTE, the
deployed md5 was re-checked in-transaction and independently afterwards: `d2a9e381…` — equal
to `docs/gov209-k3/new-def-v2.9.sql` byte-for-byte. Either the deployed bytes are exactly the
reviewed bytes, or nothing deploys.
