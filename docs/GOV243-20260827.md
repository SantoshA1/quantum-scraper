## Incident during the build — and two of my own claims corrected

v1.3's first deploy failed its smoke (663707: "Syntax error at line 7 near \"as\"")
while I had "proof" the SQL was valid. A 9-increment bisect in a throwaway workflow
(archived) found the truth: **one missing `)` in the brake block.** Both my proofs
were faulty, and the record should say so plainly:
- My paren counter was not comment-aware — a stray `)` inside my own comment masked
  the missing one in code (final depth read 0; the comment/string-aware count reads 1).
- My "direct replay of the exact bytes" was a reconstruction that unconsciously
  typed the missing paren. A replay proves nothing unless it runs the staged bytes.
- The node's error prettifier points at the line of the FIRST `as` token, not the
  offending one — the "line 7" pointer sent me down a false comment/splitter theory,
  which the bisect also disproved (comments with `;` and unbalanced brackets run fine).

**Ratchet:** suite PIM-SQL-7 now enforces comment/string-aware paren balance on the
payload before any deploy; the lesson is written at the fault site in the SQL itself.
