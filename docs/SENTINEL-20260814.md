## Why this exists

Seven guards died silently this quarter — ADX gate, MTF confluence, PF filter's cache, the
hardcoded vix, `trade_log` P&L under the kill switch, the pause-row masking, the stale
position display — every one fail-open, every one discovered weeks late by manual archaeology.
The common cause was never the guard logic; it was that **nothing asserted the guard's input was
alive.** This sentinel is that assertion, running every 15 minutes.

**Alerting discipline:** Telegram on state *change* only (new alarm, new notice, or recovery),
plus one 4-hour re-remind while an alarm stands. Signature lives in workflow staticData. A
Telegram outage can never block the evidence — every run logs all 11 results to
`quantum.guard_liveness_log` regardless.

## The shakedown caught something before deploy

First dry run flagged `vix_payload` NOTICE: **two** distinct VIX values in 24h — 24 *and* 0.
Investigation (3 queries): repeat-log rows (`SCORE_CHANGE`/`PERIODIC`) have carried `VIX: 0`
for as long as those paths existed, while `NEW_SIGNAL` rows carry the hardcoded 24. Not a new
break — a wrong belief. The check's expectation was corrected to the true state
(`values ⊆ {0,24}`), and the ledger of known defects gained a footnote: repeat signals get no
vix penalty and a different VIX regime than their originals. The sentinel's first act was to
make our own documentation more honest.
